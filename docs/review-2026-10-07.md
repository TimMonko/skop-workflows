# Review, 2026-10-07: skop-workflows and its neighbours

An overnight pass over skop-workflows, skop-napari, scikit-ops (and its
`opspec/`), and appose-python: how they fit, what was wrong, what changed, and
which designs still need a decision. Nothing here is committed or pushed;
every change is in the working trees, beside whatever was there before.

## What changed

### skop-workflows

- **A pytest suite** (`tests/`, 226 tests) beside the demo contract. Every
  store test runs against both backends; `test_with_scikit_ops.py` puts the
  recorder in front of scikit-ops' real `Runner` (workflows only, so nothing
  is built). `demo/headless.py` still passes, 89/89.
- **Recipe format 2** (decision 52): every input is `{'root': name}` or
  `{'step': name, 'output': name}`. `save`/`load` write and read
  pretty-printed JSON and refuse other formats.
- **Workflows are recorded whoever starts them** (decision 54): `Recorder.run`
  makes the recorder ambient for a workflow, so replay, update, rerun and
  produce record nested calls and run them on the recorder's runner.
- **Runner options are recorded** (decision 55): `variant`, `axes`, `plans`,
  `position` go into `Run.options` and come back on update, rerun, produce and
  replay. `InProcess` honours plans as the worker does.
- **Cancelled runs and timing** (decision 56): `Run.status` may be
  `cancelled`, and such a run never becomes current; `Run.started`,
  `Run.duration` are recorded.
- **Keeping an edit is built** (decision 57), on one new primitive,
  `Graph.now(handle)`. `Graph` also caches current runs and marks.
- **Path parameters are roots** (decision 60, which builds decision 6).
- **Stores** (decision 58): names are encoded per filesystem rules; object
  values are refused; scalars are stored as 0-d arrays; `SimpleStore` keeps
  its log in memory after the first read; `IcechunkStore` holds a lock.
- **Inputs may be any array-shaped object** (dask, zarr, xarray), known by
  identity as numpy arrays are, matching what scikit-ops' runner accepts.
- **`outputs_of(spec, result, args)`** is the one place an op's result is
  split into named outputs (NamedTuple, plain tuple, mapping, or the caller's
  buffers for computer-form ops). skop-napari's copy is gone.
- **`skop_visual.view(graph, targets)`** takes no store: root names come from
  the log. New badges: `kept`, `cancelled`.
- Docs: decisions 52–60, glossary (**Kept**, **Run**), design notes 0003–0005
  statuses, `upstream.md`, `demo.md`, and `AGENTS.md` (pytest, pitfalls, next
  steps; note that `AGENTS.md` is in `.gitignore`).

### skop-napari

- **Keep the edit** now stores the layer's pixels (`Host.keep`); a kept step
  can be reverted, and Revert unmarks before it redraws.
- **One drawing path**: `ViewerDisplay.put` draws for both the Ops panel and
  Produce/Revert, and `ViewerDisplay.show` lays boxes and masks out with
  `layer_args_for`, so a box step brought up to date by Produce is drawn as
  rectangles instead of a broken Shapes layer.
- **Export recipe…** button on the Record panel (demo step 9 had no UI).
- A layer is linked to the step's newest run, so a cancelled run's partial
  result is not mislabelled as the previous run's output.
- `Session.produce` no longer wraps itself in an ambient (the recorder does
  it); step naming moved onto the `Recorder`; runs record
  `scikit-ops <version>`.
- `tests/test_host.py` +4 (keep, paint-then-keep, revert a kept edit, draw
  kept pixels); `tests/test_record.py` +5 (keep through the panel, boxes
  redraw, scalar, export with and without targets). README now describes all
  three widgets and every module.

### scikit-ops (branch `skop-workflows`)

- `Runner._run_here` reuses an installed ambient's task instead of creating a
  task nobody holds. Without that, under a recorder, a workflow's own
  `progress()` went nowhere and its `cancel_requested()` never saw a cancel.
  Two tests in `tests/test_nested_calls.py`.
- `opspec/src/opspec/runner.py`: the Runner protocol states the nested-calls
  contract (it existed only, uncommitted, in the standalone `../opspec`).

### appose-python

Nothing changed. Read only, to confirm that a cooperative cancel leaves no
trace on the host-side `Task` (status COMPLETE). That is why the recorder
watches the cancel handle itself.

## Bugs found, worst first

1. **Replay, update, rerun and produce of a workflow ran its nested ops on
   scikit-ops' default runner, unrecorded.** Only a `RecordingRunner` made
   itself ambient. In napari that meant a second set of workers; headless, a
   replayed workflow had no children.
2. **A cancelled op's partial result was recorded as `ok` and became
   current**, so it fed Produce and recipes as if it were a result.
3. **Recipe refs were ambiguous.** `@name` could not tell a root from a step
   of the same name, which is common in napari (a layer named like a step),
   and it dropped which output of a multi-output step was read. Replay then
   handed a whole NamedTuple to the next op.
4. **`Keep the edit` made the recipe lie.** It cleared the edited mark, so
   export stopped warning, while replay recomputed the step without the edit.
5. **Layer names broke `SimpleStore` on Windows.** `ch1: DAPI` is an NTFS
   alternate data stream, `Image`/`image` collide, `con` cannot be created.
   Icechunk broke on `/` and `..`, and could not read back a scalar.
6. **Absolute paths leaked into recipes** through `Path` parameters, against
   the stated invariant.
7. **`IcechunkStore` was not thread-safe.** The napari host records off the
   GUI thread while drawing on it, and two threads committing at once failed.
8. **Plain-tuple outputs** (`-> tuple[...]`, which `Runner` returns
   unwrapped) crashed `_save`. **`Out` buffers** were recorded as parameters
   and refused as non-JSON. **`Optional[Enum]` / `Optional[Path]`** were not
   revived on rerun.
9. **Produce redrew boxes without `shape_type`.** It drew from the raw array,
   unlike the panel.
10. **Axis plans were not recorded**, so Produce on a step the panel ran plane
    by plane ran it whole (AGENTS.md listed this as the next step).

## Design critique: decisions still open

These need your decision rather than mine. Each says what I would do.

1. **The fork/monorepo decisions describe a different project.** Decisions
   13, 20, 25 and 26 call for a uv workspace monorepo with an in-repo
   scikit-ops fork consumed by git URL. In fact there are four sibling repos,
   and scikit-ops is consumed by local path from a `skop-workflows` branch.
   *Recommendation:* record what is true, "sibling repos by path until the
   hackathon ends", and supersede those four.
2. **opspec exists twice, and the copies have already drifted.**
   `../opspec` (True-North) and `scikit-ops/opspec` differ in `op.py`
   (`Out`/`Mut` exist only in the scikit-ops copy), `types.py` and
   `runner.py`. This is the drift decision 44 was written against.
   *Recommendation:* one canonical home; the other vendors it with a sync
   check, or depends on it.
3. **Handles are identities.** An `id()` plus a weakref is cheap, but any
   copy, view or `astype` is a stranger. The recorder refuses rather than
   misrecording, which is right, but the napari host has grown compensations
   (`array_for`, `sync`'s identity check). Re-declaring a lazy layer stores a
   new version even when its pixels did not change, and that makes its
   readers stale for nothing. *Recommendation:* keep identity for
   op-to-op flow, and take a content digest at root declaration only, so an
   unchanged re-declaration is a no-op.
4. **Every root declaration copies the whole array** into the store, and
   every paint-settle on a root copies it again; nothing is ever collected.
   That works against OUTLINE's zarr/dask goals. *Recommendation:* a
   *referenced* root for file-backed layers (path + reader + digest) instead
   of a copy, and Icechunk virtual references when that backend is used.
5. **Two step-naming regimes.** `Recorder.run(fn, step, …)` lets the caller
   name a step (decision 33). `RecordingRunner` names it from the op and its
   inputs (decision 50). The napari panels use only the second; `Host.run`,
   `Host.update` and `Host.rerun` are used only by tests. *Recommendation:*
   make decision 50 canonical, and keep `Host.run` explicitly as the test seam
   or remove it.
6. **Every op without an `env` is a "workflow"**, so leaf host-side ops (all
   the demo ops) install an ambient and a task on every call, and the graph
   cannot tell a leaf from a workflow until children appear. *Recommendation:*
   ask scikit-ops for an explicit marker; `env is None` overloads "runs here"
   and "calls other ops".
7. **Computer-form (`Out`) ops cannot be run from the panel** (nothing
   allocates the buffer) **or replayed from a recipe**. Update and rerun now
   allocate from the last output. *Recommendation:* the runner should
   allocate `Out` buffers from a declared rule ("like `image`"). That is a
   scikit-ops change.
8. **The Record panel's store is a temp directory**, so a session is gone at
   exit, and there is no "load recipe and replay on these layers" yet.
   *Recommendation:* a session folder chosen by the user, and a Replay
   affordance that binds recipe roots to layers through the same input
   dropdowns.
9. **`op_version` is free text**, now `scikit-ops <version>` from the napari
   host. Decision 12 (the providing package plus the environment lock digest)
   is unbuilt, and `host.INIT` putting the checkout first means even that
   version can mislead.
10. **Paused mode** (decision 8) is unbuilt, and durations are recorded but
    not shown.
